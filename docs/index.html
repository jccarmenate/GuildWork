GuildWork

Project-management system for a software consultancy: Admins and PMs run clients, projects, and bug tracking, while Developers see only what they're assigned to. Every permission is enforced server-side.

Features

Role-based tracking

Clients, projects, and bugs scoped by Admin / PM / Developer, enforced server-side.

Analytics dashboard

Bug severity, completion by client/priority, workload, skill-gap, and mentorship rollups — colorblind-safe palette.

Bug comments & attachments

Threaded discussion and file uploads (images/PDF) per bug, stored in Postgres.

Audit log

Every role change and destructive action recorded with actor, timestamp, and detail.

Self-service auth

Registration, login, password reset by email, silent token refresh via httpOnly cookie.

PDF reports & email

Server-generated per-project PDF reports; assignment and resolution email notifications.

Authorization matrix

Route / actionAdminPMDeveloper
Manage clients (CRUD)✅✅403
Create/edit/delete projects✅✅403
List all projects✅✅assigned only
Assign/unassign developers✅✅403
Edit a bug's status/notes✅✅if assigned
Reassign a bug / severity✅✅403
Change a user's role✅403403

403 means "wrong role." 404 means "doesn't exist from your vantage point" — a Developer requesting an unassigned project gets 404, not 403, so the status code can't be used to probe which projects exist.
